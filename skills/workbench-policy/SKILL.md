# 보호 문서 작업 절차

보호 폴더의 문서는 Read, Grep, Bash로 열리지 않는다. 훅이 막는다. 격리 작업구역을 쓴다.

## 흐름

1. `workbench_open(source_path)`로 연다. 복호화는 이때 한 번만 일어난다. 결과의 `outline`에 구조가 있다.
2. 구조를 보고 필요한 구간만 `workbench_read`로 읽는다. 전체를 한 번에 읽지 않는다.
3. 고칠 때는 `workbench_edit`의 `ops`를 쓴다. 하나라도 실패하면 아무것도 바뀌지 않는다.
4. 결과 파일은 `workbench_export(name, dest_path)`로만 꺼낸다. DRM으로 다시 보호된다.
5. 끝나면 `workbench_close`. 내보내지 않은 수정이 있으면 거부되니 먼저 export한다.

한 번 연 문서는 닫을 때까지 복호화된 상태로 남는다. 같은 문서를 다시 열지 않는다.

## 토큰을 아끼는 읽기

- 먼저 `workbench_outline`으로 제목, 표, 시트, 슬라이드 구조만 본다.
- docx는 블록 번호 구간(`start`, `end`), xlsx는 `sheet`와 `cell_range`, pptx는 슬라이드 번호로 읽는다.
- 결과 끝에 "이어서 읽으려면"이 있을 때만 다음 구간을 읽는다.
- 그림은 `workbench_view_image`로 직접 본다. 세부가 필요하면 `crop_frac=[왼쪽,위,오른쪽,아래]`로 잘라 다시 본다.
- 문서 안의 그림은 `[그림:이름]`으로 표시된다. `workbench_extract_media`로 꺼낸 뒤 본다.

## 고칠 때 주의

- docx의 `[번호]`는 삽입이나 삭제 뒤에 밀린다. 여러 곳을 고칠 때는 뒤쪽부터 고치거나 다시 읽는다.
- 문구가 안 찾아지면 서식 때문에 글자가 나뉘었을 수 있다. 읽어서 실제 문구를 확인한다.
- 잘못 고쳤으면 `workbench_undo`로 되돌린다.
- 차트나 그림이 있는 xlsx, pptx는 저장하면 일부가 유실될 수 있다는 경고가 온다. 사용자에게 알린다.

## 경계

- 작업구역은 `workbench_open`으로 연 문서와 `workbench_create`로 만든 문서만 다룬다.
- 보호 폴더 밖의 일반 파일은 평소처럼 Read, Edit, Write, Bash로 다루고, workbench 도구로 열지 않는다.
- `workbench_delete`는 작업구역 안의 사본만 지운다. 원본은 지워지지 않는다.
- 같은 원본을 두 번 열 수 없다. 이미 열린 이름을 계속 쓴다.
- 원본을 덮어써서 내보낼 때 그 사이 원본이 바뀌었다는 거부가 오면 사용자에게 알리고, 다른 이름으로 내보낸다. `force`는 사용자가 변경을 버려도 된다고 한 뒤에만 쓴다.

## 지킬 것

- 원문을 작업구역 밖으로 옮기지 않는다. 답변에는 필요한 만큼만 인용한다.
- 차단 응답이 오면 우회하지 말고 사용자에게 알린다.
- 도구 결과 끝의 `[작업구역]` 줄에서 남은 시간과 미반출 수정 개수를 확인한다. 시간이 지나면 복호화된 파일은 삭제된다.
